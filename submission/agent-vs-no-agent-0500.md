# 단어 대조·한 번 OCR·직구레이더: 같은 25상품 비교

## 먼저 말할 수 있는 것

1. **금지 성분 상품 17개 중 15개는 제공된 페이지 글 없이 사진만 있었다.** 단어 색칠 계산은 이 15개에 표시를 만들 수 없었고, 직구레이더는 11개에서 정답 원료를 찾고 4개는 확인 필요로 남겼다.
2. **사진을 한 번 읽는 단순 방법도 강했다.** 14개 상품에 목록 단어가 나왔지만, 그중 하나는 성분표가 아닌 주의문구였다. 독립 정답 원료를 찾은 상품은 단순 OCR과 직구레이더 모두 13개로, 검출 우위를 입증하지 못했다.
3. **이번에 보인 차이는 ‘없음’과 ‘아직 확인 못 함’을 구분하고 다음 확인을 기록하는 것이다.** 직구레이더는 못 찾은 양성 4개를 조용히 통과시키지 않았다. 이 결과를 모델의 자율 행동 선택 우위로 부르지 않는다.

## 방법을 먼저 고정

- **가-1 · 단어 색칠 방식의 대조 계산:** 같은 제공 상품 텍스트에서 식약처 공식 이름·공식 이명을 찾아 표시할 단어를 계산한다. 사진 OCR·부족 상태·다음 행동은 없다. **실제 제3자 확장을 25개에 설치·실행한 시험은 아니다.** HTML의 스크립트·메타데이터·메뉴를 무작정 검색하지 않고 상품 성분 텍스트를 쓴, 색칠 방식에 유리한 비교다.
- **가-2 · 실제 단순 스크립트:** 동결 `app/scripts/crawl_word_baseline.py`의 `run_product`를 실행한다. 원래 출력인 `match / no_match / no_evidence`를 보존한다. **이 코드 자체가 `근거 없음`을 승인으로 바꾸지 않는다.**
- **나 · 사진까지 한 번 읽기:** 가-2의 상품 글에 사진 20장의 첫 원방향 OCR 원문을 각각 한 번 더해 같은 공식 이름·이명과 대조한다. 회전·추가 대형사진 처리·혼합물 내부 성분 파싱·부족 판단·재시도·질문은 없다. 첫 OCR은 기존 실제 응답을 회수했으며 새 GPU 호출은 0이다.
- **다 · 직구레이더:** 같은 입력·정답의 25상품을 동결 **integrated-0450 실제 API**로 실행한다. 읽기·목록 대조·범위 검사·재시도·각본 질문·보완 사유와 최종 결과를 보존했다. 최신 제출 코드 0505는 별도이며 이 숫자를 0505 실측으로 바꾸어 부르지 않는다.

가-1의 비교 대상은 [2022-10-23 판매자용 공개 안내](https://enjoygood.tistory.com/entry/미국-구매대행-건강기능식품-수입-금지-성분-걸러내는-방법-필터링)가 설명한 방식이다. 식약처 목록을 Highlight This에 넣고 iHerb 페이지의 단어를 표시한다. 안내는 사진에는 이 방법을 쓸 수 없다고 구분한다. 사용 사례 하나이지 현재 보급률이나 검출 성능의 측정값은 아니다. 가-2는 실제 페이지 어댑터와 공식 이명까지 쓴 코드이고, 나는 제공 사진을 한 번씩 읽는 단순 자동화다.

## 결과 — 승인·통과로 바꿔 읽지 않는다

분모: 고정된 개발 검증셋 **양성 17, 음성 7, 별도 review 1 = 25상품**. 금지 원료 ID 정답은 기존 계획 그대로다.

| 방법 | 양성 중 목록 단어 표시 /17 | 그중 정답 원료 ID 확인 /17 | 아무 표시 없음 /17 | 그중 페이지 글 없음 | 확인 불가를 명시 /17 | 다음 확인 사유 기록 /17 | 음성 잘못 표시 /7 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 가-1 단어 색칠 계산 | 1 | 1 | 16 | 15 | 0 | 0 | 0 |
| 가-2 실제 단순 스크립트 | 1 | 1 | 0 | 0 | 16 | 0 | 0 |
| 나 원방향 OCR 한 번 + 대조 | 14 | 13 | 3 | 0 | 0 | 0 | 0 |
| 다 직구레이더 0450 | 13 | 13 | 0 | 0 | 4 | 12 | 0 |

- ‘아무 표시 없음’은 미검출 결과만 내고 확인 불가 상태를 따로 내지 않은 양성 상품이다. **안전 승인·통관 허용·실제 오통과 건수가 아니다.** 가-2의 16개는 별도 `no_evidence`이므로 이 칸에 중복으로 넣지 않았다.
- 가-2는 NIH 도메인을 지원하지 않는다. 양성의 `no_evidence` 16개 중 **15개는 처음부터 페이지 글이 없는 사진 입력, 1개는 글이 있지만 어댑터 지원 밖인 Echinacea**다. 이 1개를 판독 실패로 설명하지 않는다. 가-1에서 그 제공 글을 직접 단어 대조해도 일치는 0이었다.
- ‘다음 확인 사유’ 12개는 native `inquiry_draft`에 보완 근거·사유가 남은 양성 상품 수다. 이미 일부 금지 성분을 찾은 상품과 **겹친다**. 실제 양성 질문은 4상품이며 모두 각본 응답, 실제 사람 참여·제조사 연락은 0이다. 초안 사유 기록을 메일 발송이나 생성 문장 채택으로 세지 않았다.
- 범위 미완료를 `문제없음`으로 승인한 수는 가-1/가-2/나의 실제 계약에 없는 지표다. `0건이면 승인`이라는 별도 운영을 가정해야 계산되므로 실측 표에 넣지 않았다.

### 단순 OCR이 14인데 정답 ID는 13인 이유

Stimerex의 첫 원방향 OCR은 성분표 대신 **주의문구**를 읽었다. `Synephrine`, `Ephedrine`을 찾아 표시했지만 독립 정답 ID 5개 중 어느 것과도 일치하지 않았다. [상품별 원장](logs/comparison-0450.json)의 `ocr_source_path`·`ocr_line`·해시가 근거다.

정답 원료 기준으로 **단순 OCR만 찾은 상품은 Bacopa 220336·Goldenseal 235708**, **직구레이더만 찾은 상품은 Stimerex 48084·Echinacea 76351**이다. 양쪽 모두 13/17이며 서로 다른 실패를 보였다. 단순 OCR의 이 성공을 감추거나 ‘Zoro만 잡는다’고 하지 않는다.

또한 Nitrotest의 단순 스크립트는 5개 목록 항목에 일치하지만 그중 `Testosterone`은 혼합물 제목의 효능 표현이다. 단어 일치 수를 곧바로 실제 함유 금지 원료 수로 발표하지 않는다. 상품 양성 정답 자체는 DMAE/Yohimbine 근거로 유지된다.

## 0450과 0430, 강한 규칙 비교

- **0450의 25개 실제 실행 완료.** 0430과 상품별 최종 판정·범위·실제 지정 ID 집합·목표 ID 회수·bounded·strict가 모두 같았다. `blocked 13 / review 10 / not_found 2`, bounded 8/25·strict 7/25다. 이는 새 0450 원장으로 확인한 것이며 0430을 새 실행처럼 복제하지 않았다.
- 양성에서 미해결인 4개는 **2-Aminoisoheptane 172744, Bacopa 220336, Goldenseal 235708, Kapikachhu 247724**다. 보류 근거를 찾지 못했지만 모두 `review`로 남겼다.
- **강한 고정 순서와는 별도 2예시에서 완결된 정답 1/2로 동률**이었다([기계 판독용 결과의 `strong_fixed_comparison`](logs/comparison-0450.json)). 그 규칙도 동일 모델·도구를 사용한다. 이 25개 전체에서 강한 규칙을 이겼다는 시험은 없다.
- 영상 세 사건의 다음 행동 선택은 모두 **코드**였다. Zoro-1은 판독 가능성·범위·일부 성분 판단·문의 글·답 자료 판단을 맡았다. 회전은 읽기 도구 내부 처리다. ‘모델이 다음 행동을 골라 성능이 올랐다’고 쓰지 않는다.

## 원자료와 한계

- [0450 상품별 측정·정의·해시](logs/comparison-0450.json) · [0430 비교 기준](logs/evaluation-25.json). 출처 필드에는 개발자 컴퓨터의 절대 경로 대신 자료를 식별할 상대 경로만 남겼다.
- 계획 SHA256: `e64fca0f1bc315d017cc91abdad81b1a3924386f1df062fe111aaa995ac669af`. 같은 25개·정답·제공 자료를 유지했고 추가 수집·정답 수정은 하지 않았다.
- 저장 iHerb 페이지의 로컬 재생 주소는 기존 캡처 메타데이터의 원래 iHerb URL로 매핑해 어댑터를 선택했다. **내용은 계획에 있는 그대로**, live HTTP 없음. HTML 전체를 무차별 검색해 메뉴·스크립트 속 이름까지 오탐으로 만드는 비교는 채택하지 않았다.
- 사진 20개는 모두 **첫 OCR에 넣은 파일 SHA256 = 계획 입력 이미지 SHA256**을 확인했다. 기존 0255-q 실행에서 질문 이후 회수한 관측도 같은 최초 제공 이미지인 경우만 사용했다. 후속 사진·두 번째 OCR·회전 결과를 섞지 않았다. 공통 입력 준비는 이미 RGB JPEG quality90·최대3200px였고, ‘원방향 한 번’은 그 제공 바이트에 추가 처리를 하지 않았다는 뜻이다.
- 개발 중 반복 관찰한 검증셋이다. 미사용 holdout 정확도·일반 안전성·SKU 판본 일치·비용·속도 우위는 아니다. 실제 외부 쇼핑몰에서의 성공률이나 실제 사람의 업무 완료율도 측정하지 않았다.
- 이 비교표는 **0450 실제 API** 결과다. 0430 촬영이나 0505 제출 코드에서 다시 측정한 비교표로 읽지 않는다.

## 제출판 0505의 별도 25상품 검증

동일한 고정 입력 25개를 **0505 실제 API**로 별도 검사했다. 정해 둔 범위에서 판정을 맞게 끝낸 상품은 8/25, 전 항목까지 끝낸 상품은 7/25, 양성 정답 원료 ID는 13/17이었다. 나머지 양성 4개는 직접 확인으로 남았다. 0430과 비교한 상품별 여섯 필드, 호출 집계, 성분 자료 채택 결과에는 차이가 없었다([비교 원장](logs/comparison-0505.json)).

오차단·잘못된 안전 표시·전송 오류는 관측된 각각 0건이다. 도구 57회, head 판단 74회, 갤러리 20회, 실제 OCR 응답 23회, 방향 판단 20회, 캐시 재사용 7회, 전체 전송 137회였다. 서로 다른 단계의 수치라 합산하지 않는다. 질문 5회에 스크립트가 답했고 실제 참여자는 0명이었다. 사건 내부 시간 합계는 483.5287초다. 이 시험은 실시간 쇼핑몰, 한국어 성분별 대화, 후속 사진 UI를 검증하지 않았다.
