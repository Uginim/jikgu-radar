# 서버 오류가 났을 때 어떤 검사가 끝나고, 어떤 검사가 멈췄나요?

**추가 시험 11건에서 앱 서버는 계속 응답했고, 상품 전체를 ‘문제 없음’으로 판정한 검사는 없었습니다. 하지만 오류를 모두 처리한 것은 아닙니다.** 검사가 끝나지 않은 경우가 5건이었고, 앱이 유효하지 않은 확률을 그대로 받아들인 경우가 2건이었습니다.

## 대역 서버로 고장을 넣어 확인한 결과

2026-11-20 07:23–07:30 KST, 검수자는 제출한 코드를 바꾸지 않고 판정 서버의 응답을 대역 서버로 바꿔 10건을 검사했습니다. 잘못된 응답은 실제 Zoro-1이 낸 답이 아닙니다. 별도의 1건에서는 실제 Zoro-1을 그대로 쓰고 글자 읽기(OCR) 연결만 실패하게 했습니다. 아래 문의 초안 확인은 이 11건과 별개입니다.

| 무엇을 확인했나요? | 앱이 실제로 한 일 | 이 결과가 뜻하는 것 |
|---|---|---|
| 서버가 살아 있으면 검사도 끝난 것인가요? | 11건 모두 검사 직후 앱 서버가 상태 조회에 응답했습니다. 상품 전체가 ‘문제 없음’으로 끝난 경우는 0건이었습니다. | 서버가 응답했다는 사실만으로 개별 검사가 끝났거나 사람이 확인할 수 있게 넘겼다고 볼 수 없습니다. |
| 판정 응답을 해석할 수 없을 때 | JSON이 아닌 응답 2건, `answers`가 없는 응답 2건, 본문 검사에서 요청하지 않은 선택지 키가 온 1건에서 화면은 “서버 실행 오류 · 완료되지 않음: 검사를 마치지 못했어요.”라고 알렸습니다. 서버에 남은 검사 상태는 진행 중(`running`)이었고 최종 판정은 없었습니다. | **알려진 결함: 5건에서 검사가 끝나지 않았습니다.** 같은 잘못된 키를 받은 사진 검사는 “직접 확인 필요”로 끝났지만, 앱은 응답 형식이 아니라 사진 품질을 문제로 안내했습니다. |
| 판정 응답의 확률이 0보다 작거나 1보다 클 때 | 본문과 사진 검사 2건에서 앱은 확률 1.2와 -0.2를 거절하지 않았습니다. 두 검사 모두 코드가 차단 목록과 일치하는 원료를 찾아 “등록 보류 권고”로 끝났습니다. | **알려진 결함: 앱이 유효하지 않은 확률을 판단에 사용했습니다.** 이 상품에서 차단 원료를 찾은 것은 확률을 검증했다는 뜻이 아닙니다. |
| 글자 읽기만 실패할 때 | 실제 Zoro-1은 3회 정상 응답했습니다. OCR 요청은 2건이었고, 앱은 각 요청을 처음 1회와 재시도 2회씩 **총 6회** 보냈습니다. 모두 실패한 뒤 사진 영역을 묻는 질문에도 답이 없자 앱은 “직접 확인 필요”로 검사를 마쳤습니다. | 사람에게 확인을 요청했지만, 기본 화면은 연결 장애보다 성분표 자료가 부족하다는 점을 강조했습니다. 실제 GPU 서버를 끈 시험은 아닙니다. |
| 다시 받은 사진도 읽을 수 없을 때, 어떤 문의를 쓰나요? | 검수자가 앞선 검사의 마지막 기록으로 문의 작성만 다시 실행하자 실제 모델이 “현재 포장의 성분 표시 전체를 읽을 수 있는 사진을 보내 주시겠습니까?”라는 초안을 만들었습니다. | 사진을 다시 요청하는 **문안**을 확인했습니다. 원래 화면에서 “문의 초안 만들기”를 다시 눌러 새 초안이 뜨는 과정은 확인하지 않았으며, 문의를 발송하지도 않았습니다. |

대역 서버가 HTTP 500을 돌려준 나머지 2건에서 본문 검사는 이미 찾은 차단 근거를 남겼고 사진 검사는 “직접 확인 필요”로 끝났습니다. 이 결과를 근거로 다른 상품에서도 오류를 항상 처리한다고 말할 수는 없습니다.

## 앞선 시험: 실제 모델 연결과 추가 사진

2026-11-20 05:29–05:37 KST, 확정 코드 `integrated-0505`와 실제 원격 Zoro-1·GravityOCR-KO를 사용했다. 격리한 Chrome의 실제 확장에서 클릭·파일 선택·후속 제출을 했다. 쇼핑몰은 라이브 사이트가 아니라 저장한 페이지 또는 성분표 없는 시험 페이지였다. 추가 사진은 시험자가 보유한 자료이며 문의 초안을 발송하거나 제조사의 실제 답변을 받은 일은 없다. 개발 원본 로그·캡처·상품 사진은 공개하지 않는다.

| 상황 | 조건과 실제 화면 | 판정과 남은 한계 |
|---|---|---|
| A1. 사진 글자를 읽는 서버가 응답하지 않음 | 실제 서버 연결의 제한시간을 0.01초로 줄였다. OCR과 판정 요청이 함께 실패했고 ‘직접 확인 필요’와 사진·영역·문의 선택이 나왔다. | 성분 0개를 대조한 뒤 사람에게 확인을 요청했다. 이 시험은 두 요청이 함께 실패한 경우다. OCR만 실패한 경우는 위 추가 시험에서 따로 확인했다. |
| A2. Zoro-1 제한시간 초과 | 같은 제한시간으로 앞면 사진을 올렸다. 방향·판정 요청이 실패했고 ‘전체 성분 검토 미완료’가 나왔다. | **통과한 범위: 오류 후 종료·인계.** 무한 대기하지 않았다. 서버 복구나 전체 검토 성공은 아니며 화면에 제한시간 원인이 직접 나오지 않는다. |
| A3. 실제 판정 서버의 응답 형식 | 처음 받은 HTTP 200 응답 28개는 모두 JSON이었다. | 실제 모델의 정상 응답만으로는 오류 처리를 평가할 수 없다. 잘못된 응답을 대역 서버로 넣었을 때 확인한 두 결함은 위 표에 적었다. |
| A4. 성분표 없는 상품 페이지 | 제목·앞면만 있는 시험 페이지를 검사하고 영역 요청에 답하지 않았다. ‘글자 판독 점수 0.22 · 기준 0.85에 못 미쳤어요.’와 ‘문의 초안 만들기’가 나왔다. | **통과한 범위: 자료 없음 인계.** 15초 뒤 확인 필요, 남은 확인 6건. 이 시험의 대기시간은 기본값 300초보다 짧다. |
| A5. 보안 확인 화면 | 저장한 GNC 보안 화면을 검사하자 ‘상품 상세 페이지가 아닙니다. 상품을 연 뒤 다시 검사’가 나왔다. | **부분.** 검사 API 요청 0건으로 잘못된 검사를 막았지만, 보안 확인 화면임을 정확히 안내하지 못했다. 서버에 검사 기록이 생기지 않았다. |
| A6-a. 손상된 사진 | PNG 파일 서명은 맞지만 이미지 내용이 깨진 파일을 받았다. OCR·판정 서버가 각각 HTTP 400을 반환했다. 화면에는 ‘글자가 선명한 성분표가 필요해요.’가 나왔다. | **통과한 범위: 실패 후 인계.** 성분 0개, 확인 필요. 업로드 전에 걸러내거나 파일 손상이라고 설명하지는 못했다. |
| A6-b. 너무 작은 사진 | 흰색 1×1 PNG에서 ‘글자 판독 점수 0.12 · 기준 0.85에 못 미쳤어요.’와 ‘문의 초안 만들기’가 나왔다. | **통과한 범위: 근거 없는 완료 방지.** 성분 0개, 남은 확인 6건. 크기만으로 업로드를 거절하지 않았다. |
| B1. 앞면 → 문의 초안 → 성분표 사진 | ‘답 붙여 넣고 이어서 확인’에 라벨을 넣고 ‘같은 검사 다시 판단’을 누르자 ‘추가된 성분 2개 · 다시 판단한 항목 2개’가 나왔다. | **재개 기능 통과 / 전체 검토 미완료.** 같은 검사에서 성분 0→2개, 남은 확인 6→4건. 후속 OCR은 성공했지만 이전 시점의 판독 실패 설명도 남았다. |
| B2. 앞면 → 문의 초안 → 또 읽을 수 없는 사진 | 같은 검사에 흰색 1×1 사진을 넣자 ‘추가 없음: 읽은 줄에서 성분 이름과 함량 또는 성분 선언을 연결하지 못했습니다’가 나왔다. | **통과한 범위: 근거 없는 재판정 중단.** 추가·재판정 0개, 남은 확인 6건. 새 자료·문의 선택을 다시 보였고 문의를 자동 반복하지 않았다. |

**앞선 시험의 재시도 횟수.** A1과 A2는 같은 장애 조건이다. 각 사례에서 방향 확인, OCR, 판정 요청을 각각 최초 1회와 재시도 2회(대기 2초·4초), 총 9회 시도했다. A6-b에서 사진을 세 방향으로 읽은 것은 통신 실패로 같은 요청을 세 번 보낸 것이 아니다. 앞선 시험에서 관찰한 네트워크 요청은 48회(HTTP 200 응답 28회, HTTP 400 응답 2회, 응답 미수신 18회)다. 이 수에는 위 추가 시험의 요청을 넣지 않았다.
