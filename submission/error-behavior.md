# 오류가 나거나 자료가 부족할 때: 0505 실측

**서버가 응답하지 않거나 성분표를 확보하지 못한 사례에서 앱은 ‘문제 없음’으로 끝내지 않았다.** 추가 라벨로 같은 검사를 이어 갈 수 있었지만 전체 검토가 끝난 것은 아니다. 글자 읽기 서버만의 장애는 분리하지 못했고, 모델이 잘못된 형식으로 응답한 경우는 재현하지 못했다. 아래는 관찰한 동작이지 모든 오류를 처리한다는 보증이나 점수표가 아니다.

2026-11-20 05:29–05:37 KST, 확정 코드 `integrated-0505`와 실제 원격 Zoro-1·GravityOCR-KO를 사용했다. 격리한 Chrome의 실제 확장에서 클릭·파일 선택·후속 제출을 했다. 쇼핑몰은 라이브 사이트가 아니라 저장한 페이지 또는 성분표 없는 시험 페이지였다. 추가 사진은 시험자가 보유한 자료이며 문의 초안을 발송하거나 제조사의 실제 답변을 받은 일은 없다. 개발 원본 로그·캡처·상품 사진은 공개하지 않는다.

| 상황 | 조건과 실제 화면 | 판정과 남은 한계 |
|---|---|---|
| A1. 사진 글자를 읽는 서버가 응답하지 않음 | 실제 서버 연결의 제한시간을 0.01초로 줄였다. OCR과 판정 요청이 함께 실패했고 ‘직접 확인 필요’와 사진·영역·문의 선택이 나왔다. | **부분.** 대조 0개, 확인 필요로 종료. 통신 실패 후 인계는 봤지만 OCR 단독 장애나 서버 자체 정지는 검증하지 못했다. |
| A2. Zoro-1 제한시간 초과 | 같은 제한시간으로 앞면 사진을 올렸다. 방향·판정 요청이 실패했고 ‘전체 성분 검토 미완료’가 나왔다. | **통과한 범위: 오류 후 종료·인계.** 무한 대기하지 않았다. 서버 복구나 전체 검토 성공은 아니며 화면에 제한시간 원인이 직접 나오지 않는다. |
| A3. Zoro-1 응답 형식이 잘못됨 | 정상 응답을 관찰했지만 형식 오류 응답이나 그 오류 화면을 보지 못했다. | **재현 못 함.** 잘못 통과할지는 판단 불가. HTTP 200 응답 28개가 JSON이었다는 관찰로 형식 오류 처리를 통과로 세지 않는다. |
| A4. 성분표 없는 상품 페이지 | 제목·앞면만 있는 시험 페이지를 검사하고 영역 요청에 답하지 않았다. ‘글자 판독 점수 0.22 · 기준 0.85에 못 미쳤어요.’와 ‘문의 초안 만들기’가 나왔다. | **통과한 범위: 자료 없음 인계.** 15초 뒤 확인 필요, 남은 확인 6건. 이 시험의 대기시간은 기본값 300초보다 짧다. |
| A5. 보안 확인 화면 | 저장한 GNC 보안 화면을 검사하자 ‘상품 상세 페이지가 아닙니다. 상품을 연 뒤 다시 검사’가 나왔다. | **부분.** 검사 API 요청 0건으로 잘못된 검사를 막았지만, 보안 확인 화면임을 정확히 안내하지 못했다. 서버에 검사 기록이 생기지 않았다. |
| A6-a. 손상된 사진 | PNG 파일 서명은 맞지만 이미지 내용이 깨진 파일을 받았다. OCR·판정 서버가 각각 HTTP 400을 반환했다. 화면에는 ‘글자가 선명한 성분표가 필요해요.’가 나왔다. | **통과한 범위: 실패 후 인계.** 성분 0개, 확인 필요. 업로드 전에 걸러내거나 파일 손상이라고 설명하지는 못했다. |
| A6-b. 너무 작은 사진 | 흰색 1×1 PNG에서 ‘글자 판독 점수 0.12 · 기준 0.85에 못 미쳤어요.’와 ‘문의 초안 만들기’가 나왔다. | **통과한 범위: 근거 없는 완료 방지.** 성분 0개, 남은 확인 6건. 크기만으로 업로드를 거절하지 않았다. |
| B1. 앞면 → 문의 초안 → 성분표 사진 | ‘답 붙여 넣고 이어서 확인’에 라벨을 넣고 ‘같은 검사 다시 판단’을 누르자 ‘추가된 성분 2개 · 다시 판단한 항목 2개’가 나왔다. | **재개 기능 통과 / 전체 검토 미완료.** 같은 검사에서 성분 0→2개, 남은 확인 6→4건. 후속 OCR은 성공했지만 이전 시점의 판독 실패 설명도 남았다. |
| B2. 앞면 → 문의 초안 → 또 읽을 수 없는 사진 | 같은 검사에 흰색 1×1 사진을 넣자 ‘추가 없음: 읽은 줄에서 성분 이름과 함량 또는 성분 선언을 연결하지 못했습니다’가 나왔다. | **통과한 범위: 근거 없는 재판정 중단.** 추가·재판정 0개, 남은 확인 6건. 새 자료·문의 선택을 다시 보였고 문의를 자동 반복하지 않았다. |

**재시도 수 읽는 법.** A1·A2는 같은 장애 조건이다. 각 사례에서 방향·OCR·판정 세 호출을 각각 최초 1회와 재시도 2회(대기 2초·4초), 총 9회 시도했다. A6-b의 세 방향 판독은 통신 실패 재시도 세 번이라는 뜻이 아니다. 전체 관측은 네트워크 요청 48회(HTTP 200 응답 28회, HTTP 400 응답 2회, 응답 미수신 18회)이며 사용자 성공 건수가 아니다.
